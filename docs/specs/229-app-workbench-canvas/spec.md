# App Workbench Canvas — Product Specification

This is the canonical product contract for the Workbench spatial planning surface.

## References

- **Parent spec**: [App Workbench](../220-app-workbench/spec.md); shell host: [Workbench Shell](../227-app-workbench-shell/spec.md).
- **Architecture decision**: [ADR-0009](../../adr/ADR-0009-react-flow-json-canvas-projection.md) — React Flow is the controlled interaction projection while JSON Canvas remains authoritative.
- **Scope boundary**: Canvas owns user-authored planning and declared spec-to-spec dependency maps; [228-app-workbench-impact-lens](../228-app-workbench-impact-lens/spec.md) owns computed reverse code/test traceability and verification health.
- **JSON Canvas spec 1.0**: <https://jsoncanvas.org/spec/1.0/> — the on-disk format (node types `text`/`file`/`link`/`group`, optional `nodes`/`edges`, `fromEnd`/`toEnd`, file `subpath`, six color presets).
- **Settings surface owner**: [214-app-chat-settings](../214-app-chat-settings/spec.md) — the chat Settings webview that hosts the Experimental toggle (FR-22) is co-owned here and there.
- **Storage**: legacy `.afx/project.canvas` remains the default project map; additional AFX canvases default to `.afx/canvases/*.canvas`, and New canvas can optionally target any folder inside an open workspace root.
- **Markdown renderer reused**: `apps/workbench/src/lib/markdown-render.ts` (`MinimalMarkdown`) for inline node content.
- **Delivery boundary**: checked acceptance criteria and Phases 1–16 in `tasks.md` describe the current release program. The unchecked Phase 16 release-foundation repairs and E2E matrix are blocking gates, not implied completion. FR-34–FR-44 and Phases 17–24 define the post-2.4.0 full-feature architecture-workbench program; they are not 2.4.0 shipping claims.

## Problem Statement

Spec-driven development has a cold-start problem: the blank `spec.md` front-loads ceremony before the user knows what they are building. AFX answers this for _linear_ thinking — chat-first, Spec mode on demand. What is missing, for a heavy SDD user, is a place to think _spatially_ before anything is a spec: drop fragments, arrange them, link them, and let an idea harden at its own pace.

The feature fills that gap with an in-IDE spatial architecture and planning workbench. It must also stand on its own as a useful general canvas when a workspace has no AFX files, specs, skills, or chat integration. Users can keep several portable canvases, arrange ordinary ideas and files, choose freeform planning or architecture/spec-map tools, inspect a whole workspace's declared dependencies when available, render the sources behind the map, and optionally hand selected context to AFX workflows. Its north star is the spatial freedom and finish associated with Miro, Jamboard, and Figma, specialized for software architecture and planning rather than general-purpose illustration.

The surface is rendered with React Flow but stored as JSON Canvas. It must be trustworthy under heavy use: acknowledged saves, independent dirty state per document, live external-file updates, explicit conflicts, undo/redo, mature selection and connector behavior, and no silent migration of existing files.

## User Stories

### Primary Users

- **Beginners and non-AFX users** who need a zero-setup whiteboard for thoughts, files, links, images, and simple relationships without learning SDD vocabulary.
- **General software teams and product planners** who want portable planning, roadmap, and presentation canvases in any workspace.
- **Architects and advanced users** who need whole-workspace topology, semantic relationships, rich composition, auto-layout, and push-limit graph navigation.
- **AFX authors and heavy SDD users** who want Notes, Boards, Chat, specs, sprints, dependency refresh, and allowlisted actions layered onto the same portable canvas.

### Stories

**As a** first-time canvas user **I want** an uncluttered default with a few obvious starter actions and plain-language empty-state guidance **So that** I can make a useful board without understanding AFX, JSON Canvas, graph terminology, or every advanced control.

**As a** non-AFX user **I want** to open or create a standard `.canvas`, add text, files, images, links, groups, colors, and relationships, and save it normally **So that** the tool is valuable in any workspace and does not require AFX metadata or conventions.

**As a** growing user **I want** to switch between Essentials, Architecture, and AFX tool profiles without converting the file or hiding content **So that** complexity appears when I need it and the same canvas can mature with me.

**As a** heavy SDD user **I want** a freeform canvas inside the Workbench where I can drop idea cards, roadmap stages, risks, and questions **So that** I can plan the next spec or feature spatially before committing to durable documents.

**As a** user mid-ideation **I want** to pull an existing markdown doc onto the canvas and read it inline next to my thoughts **So that** I can relate messy thinking to durable artifacts in one view.

**As a** user with a maturing idea **I want** to select a card and send it to chat as context **So that** a thought can become durable project memory without losing its messy source.

**As a** user organizing fragments **I want** to resize cards, draw labeled links, group them in a box, and color them **So that** the spatial arrangement itself carries meaning.

**As a** spec maintainer **I want** a spec-map mode that imports declared `depends_on` relationships without destroying manual layout or connections **So that** I can understand and plan feature dependencies from the same spatial surface.

**As a** roadmap owner **I want** several named canvas files with planning templates and an explicit next-spec handoff **So that** ideas, features, releases, and experiments do not compete for one project map.

**As an** architect **I want** to map every workspace spec and its dependencies, drill into rendered source, and reorganize the graph without losing my manual composition **So that** the canvas becomes an enduring architecture model rather than a one-off diagram.

**As a** product planner **I want** local images, safe URL previews, Notes, Boards, files, and rendered Markdown beside low- or high-fidelity frames **So that** research, delivery state, and design intent stay attached to the architecture.

**As a** power user **I want** rich connector styles, colors, groups, selection tools, and previewable auto-layout **So that** I can move between rapid whiteboarding and presentation-quality architecture maps without rebuilding the canvas.

**As the** maintainer of a portable workspace **I want** every canvas stored as standard JSON Canvas **So that** it is diff-able, commit-able, and openable by other JSON Canvas tools without lock-in.

**As the** product owner running an experiment **I want** the feature off by default behind a flag with a pre-committed kill criterion **So that** building it is cheap to validate and cheap to remove.

## Success Measures

Success is based on completed workflows and trustworthy depth, not raw Canvas-tab opens or node counts. Automated evidence is required wherever the outcome is deterministic; any human usability sample is recorded separately and never inferred from test automation.

## Acceptance Criteria

### Gating & Persistence

- [x] With `afx.experimental.canvas` unset/false, the Workbench shows the original seven tabs and no Canvas surface, file read/watch, or `canvas` payload exists (`canvasEnabled:false` in `afxUpdate` is allowed).
- [x] With the flag true, a `Canvas` tab appears and opens an infinite canvas surface.
- [x] First open with no `.afx/project.canvas` present shows an empty canvas; creating the first node creates `.afx/` if missing and writes a valid `.canvas` file.
- [ ] Editing a canvas keeps it dirty until the matching host acknowledgement; failures remain retryable and a newer manual edit produces an explicit conflict instead of being overwritten.
- [ ] Switching Workbench tabs, Canvas files, or editor-area instances before a debounce completes cannot lose the pending edit.

### Authoring

- [x] A created text node stores its markdown inline; reloading the canvas restores it identically.
- [x] A file node pointing at an existing `.md` renders that file's markdown inline via the shared renderer; unsupported files show a filename/type card.
- [x] Dragging a node updates its `x`/`y`; resizing updates `width`/`height`; both persist across reload.
- [x] Connecting two nodes creates an edge; adding a label persists it; retargeting/deleting an edge persists; the edge survives reload.
- [x] Pan and zoom move/scale the viewport without moving nodes relative to each other.
- [x] Note/label/group nodes, per-node color, and node rename author correctly and persist _(FR-23)_.

### Fidelity, Live actions & Settings

- [x] Loading a `.canvas` authored in Obsidian (containing `group`/`link` nodes, colors, edge sides, subpaths) renders without error and, after an AFX edit + save, retains every original node type and field — and AFX `afxNodeKind` extension fields round-trip losslessly _(FR-13/18, NFR-3)_.
- [x] Promoting a text node appends a quick note and leaves the source node intact _(FR-15)_.
- [x] Selecting nodes and "send to chat" sends the selected content via `afxOpenChatCommand { mode: "send" }` _(FR-16)_.
- [x] A file node for an existing markdown file selects via `afxPickMarkdownFile`/`afxMarkdownFilePicked` and renders the returned `afxDocContent`; a missing/non-markdown file never attempts direct webview file IO _(FR-20)_.
- [x] Chat Settings → Experimental shows the Workbench Canvas toggle; flipping it sends `experimental/setCanvasEnabled` and the Workbench tab appears/disappears _(FR-22)_.
- [ ] Manually editing a canvas or a referenced markdown file refreshes every clean Workbench/editor-area consumer without reopening the view; a dirty consumer receives a conflict choice.

### Canvas Library, Modes & Planning

- [ ] `.afx/project.canvas` appears as the backward-compatible Project Canvas and is never silently moved; users can create, rename, duplicate, select, and delete `.afx/canvases/*.canvas` documents with collision-safe host operations.
- [ ] Freeform mode generates no dependency content and offers blank, ideas, feature-plan, and roadmap starters that remain ordinary editable JSON Canvas nodes and edges.
- [ ] Spec Map imports canonical `depends_on`, distinguishes resolved, unresolved, and cyclic relationships, preserves manual layout/content, and refreshes generated edges idempotently.
- [ ] Generated dependency edges are visually distinct, locked until detached, and never cause manual edges or styling to be removed.
- [ ] Next Spec previews the exact selected context and AFX spec/sprint command before sending it to Chat; it never silently creates or rewrites a spec.

### React Flow & Editor Area

- [ ] The React Flow projection preserves legacy canvases, unknown fields, groups, links, parallel edges, endpoint semantics, colors, labels, and extension data after edit/save/reload.
- [ ] Lasso, multi-select, keyboard delete, copy/paste/duplicate, undo/redo, snap, auto-pan, fit view/selection, reconnect, resize, controls, and optional minimap work by pointer and keyboard without trapping focus.
- [ ] Bezier, straight, step, and smooth-step routes plus solid, dashed, and dotted strokes, markers, labels, and colors persist across reload.
- [ ] Open in Canvas Editor opens a focused editor-area view for the same document; edits, dirty/conflict state, undo/redo, and manual file changes stay coherent with the Workbench view.
- [ ] The 150-node/200-edge interaction benchmark, bundle size gate, reduced-motion checks, and narrow responsive captures pass.

### AFX-enhanced JSON Canvas Compatibility

- [ ] AFX-authored files contain valid JSON Canvas 1.0 `text`, `file`, `link`, `group`, and edge records; ignoring all `afx*` metadata leaves a readable, spatially equivalent canvas.
- [ ] AFX round-trips fixtures from Obsidian-compatible tools without dropping unknown fields, z-order, geometry, subpaths, endpoints, colors, labels, groups, links, or parallel edges.
- [ ] AFX action cards retain meaningful standard text/file/link content, render inertly outside AFX, and never execute on open, import, dependency refresh, or external-file update.
- [ ] Untrusted, unsupported, malformed, or non-allowlisted action metadata is inert and visibly explained; consequential actions preview their exact command/context and require confirmation.

### Progressive Profiles & Universal Use

- [ ] Essentials is the first-run default and exposes a plain-language empty state plus the minimum add/connect/group/color/open/save/undo/redo/export controls needed to complete the beginner success script.
- [ ] Architecture and AFX profiles progressively reveal their owned tools over the same document; switching profiles changes no document bytes, never hides authored content, preserves core shortcuts, and offers command search for less-visible actions.
- [ ] With no `.afx/`, specs, Chat, Notes, Boards, or skills available, the universal baseline remains fully usable; capability-dependent actions are absent or explain why they are unavailable and how to enable them.
- [ ] The same standard canvas opens in each profile and in an Obsidian-compatible tool without conversion, required proprietary node types, or machine-specific workspace roots.

### Release Foundation Re-audit (blocking before advanced phases)

- [ ] A stable per-document host session owns the document/session/sequence edit stream, dirty state, pending results, latest-wins queue/save timer, history, mode, and profile outside transient tab/editor React lifetimes; open-`TextDocument` edits apply immediately, disk-only edits may debounce 650 ms, and switching/closing/unmounting flushes or secures the latest content.
- [ ] Referenced-content subscriptions use node owner identity + portable path + subpath + revision, invalidate on manual `.md`/`.markdown` changes, ignore stale/cross-root responses, and fetch full bodies only for visible, expanded, or explicitly requested nodes.
- [ ] Spec discovery covers four-file specs and single-document Sprints across every workspace root without a silent cap; generated node preview/open actions resolve against the node's owner, not the active canvas owner.
- [ ] Dependency refresh is idempotent after repeated refresh/detach cycles: detaching creates a fresh manual identity, persists suppression/provenance, never duplicates an edge ID, and never deletes manual style or geometry.
- [ ] React Flow parity includes authoring node colors, link URL/open, group rename/background, multi-file insertion, and multi-selected Chat; anything displayed but intentionally immutable is visibly read-only.
- [ ] Same-document external replacement rebases or explicitly invalidates undo/redo history; named documents retain their title, mode, profile, viewport, selection, and independent save state across switches and split clients.
- [ ] Real extension-host E2E—not only a mocked browser bridge—covers immediate tab switch, editor close/hot exit, stale acknowledgements, write failure/retry, multi-root source open/preview, `.markdown`, repeated dependency detach/refresh, capability-off Essentials, touch/keyboard, high contrast, reduced motion, and packaged VSIX behavior.

### Full-Feature Architecture Workbench (post-2.4.0)

- [ ] Essentials, Architecture, and AFX profiles pass their outcome scripts on the same mixed canvas; profile switching is non-mutating and the capability-off workflow remains complete.
- [ ] Whole-workspace discovery maps every spec and declared dependency, supports search/filter/focus/traversal, and exposes unresolved, orphaned, and cyclic relationships without rewriting source specs.
- [ ] Spec/Markdown, general file, local image, and URL nodes render the appropriate live/safe presentation with source identity, loading/error/blocked states, and explicit open actions.
- [ ] Notes and Boards attach as file-backed live nodes, update after manual edits, and open in their owning Workbench tool without duplicating ownership.
- [ ] Low-fidelity ideation and high-fidelity presentation scenarios support frames, reusable templates, alignment/distribution, locking, z-order, styling, semantic shapes, annotations, and presentation mode.
- [ ] Full-canvas and selection auto-layout previews at least hierarchical, dependency, radial, grid, swimlane, and compact results; Cancel changes nothing, Apply is one undo step, and pinned/manual/group geometry is preserved.
- [ ] Rich connector/group scenarios cover route/stroke/marker/color/label/waypoint/parallel-edge combinations, multi-edit, nested collapse/expand, generated-edge detach, and reload fidelity.
- [ ] Push-limit E2E exercises mixed rendered content, the complete practical React Flow interaction matrix, 360 px and desktop/editor-area layouts, 1,000-node/2,000-edge stress, external edits, conflicts, undo/redo, layout, export, accessibility, and visual captures.
- [ ] Ignoring all `afx*` metadata leaves a valid, readable JSON Canvas whose standard nodes, files, links, groups, colors, geometry, and relationships remain useful in Obsidian-compatible tools.

## Non-Goals (Out of Scope)

- Computed reverse **source/test/orphan/verification impact** — owned by `228-app-workbench-impact-lens`; Canvas imports only declared spec dependencies.
- Inline **PDF, video, arbitrary iframe, or live-HTML** execution inside nodes. Local images and sanitized URL metadata/image previews are in scope; arbitrary remote documents are not.
- **Multiplayer / real-time collaboration**, comments, presence.
- Pixel-level vector illustration, freehand brush simulation, and an unrestricted third-party plugin ecosystem; the north star is architecture/planning composition, not replacement of a dedicated illustration editor.
- **Rich WYSIWYG markdown editing** inside a node (edit the source; render markdown — no in-node rich editor).
- Silent spec creation, automatic rewriting of `depends_on`, or automatic movement of manually positioned nodes.
- Automatic execution of commands embedded in a canvas file.
- Full project scheduling semantics such as resource allocation, critical-path accounting, and timesheets.
- Separate Essentials/Architecture/AFX file formats or destructive profile conversions; profiles are progressive UI over one portable document.
- Product success based only on Canvas opens, created-node counts, or screenshot volume without completed-workflow, reliability, portability, and performance evidence.
